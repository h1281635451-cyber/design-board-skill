# 领域与内容模块

选择一个主领域，必要时增加一个辅助领域。以下是设计展示建议，不是赛事官方评分规则。

## 领域路由

- **工业产品/智能硬件/家具/交通/穿戴**：问题、场景、功能原理、结构、三视图、人机、CMF、制造、交互、样机和验证。
- **医疗健康**：角色与工作流、风险、隐私、误用防护、清洁、可达性和验证边界；禁止声称未经证实的医疗效果。
- **数字交互/UI/UX/交互装置**：用户目标、任务路径、信息架构、关键状态、异常流程、原型和测试；不要只堆 UI 截图。
- **服务设计**：利益相关者、旅程、触点、服务蓝图、前后台机制和实施路线。
- **品牌/VIS/包装/文化创新**：文化依据、定位、识别生成、规范、结构、材料和应用；避免传统元素堆砌。
- **可持续/跨学科**：系统边界、材料和能源、影响路径、权衡、指标来源和各学科贡献。

## 可复用模块

| 模块 | 所需输入 | 推荐表达 | 缺失时 |
|---|---|---|---|
| 问题场景 | 真实人物、任务、痛点来源 | 场景图与短注释 | 标“假设场景” |
| 用户研究 | 方法、样本、原始记录 | 洞察卡、聚类、引语 | 展示研究计划，不生成结果 |
| 竞品/现状 | 来源、评价维度 | 对比矩阵、定位图 | 标“初步假设，待核实” |
| 功能原理 | 输入、输出、部件依据 | 原理流程、剖视 | 标“概念机制，待工程验证” |
| 结构/尺寸 | CAD、部件、真实尺寸 | 爆炸图、三视图、人机 | 不补写内部件，尺寸留待测量 |
| 任务流程 | 步骤、分支、异常 | 流程图、状态机 | 仅画主路径并列缺失状态 |
| 服务蓝图 | 角色、触点、后台 | 分层蓝图 | 标责任关系待确认 |
| 测试验证 | 任务、样本、指标、记录 | 结果、限制和版本变化 | 只给测试方案，不生成结果 |
| 场景落地 | 实物、地点、使用记录 | 真实照片与说明 | 概念效果图必须标非实拍 |

## 主张—证据—视觉表达

每个关键主张都要回答：凭什么成立，如何让评审看见。没有证据时降低表述强度。例如：

```text
主张：适合单手操作
证据：真实尺寸、握持样机、任务测试（若存在）
视觉：手部场景、尺寸线、测试摘要
无证据：标“人体工学概念假设，待样机验证”
```
