# 提示词深度质量规范

最终提示词不是栏目摘要。生成前先建立四层工作底稿，再把与当前展板有关的信息完整展开为六段。四层负责“想清楚”，六段负责“写到可执行”。

## 四层工作底稿

### Project Bible

记录中英文名称、一句话定位、问题、目标用户、使用场景、设计类型、核心价值、任务流程、功能映射、可见组成、主体轮廓与比例、操作部位、状态变化、CMF、反馈、差异点、项目阶段及证据。产品类必须写清部件相对位置与操作姿态；IP、UX、品牌类分别锁定角色特征、界面状态或识别系统。

纹样与文化图形项目额外记录文化来源与权利状态、对象分类、原型局部、基本单元、中心/边饰、对称/旋转/镜像或平移规则、二方/四方连续边界、线宽、色彩层级和载体裁切；具体字段见 `references/pattern-design.md`。

每个字段只能处于一种状态：

- **已确认事实**：来自用户材料或已核实来源，可直接陈述；
- **概念假设**：为推进设计而提出，必须标注“建议，待用户确认”；
- **待补证据**：允许展示研究或测试计划，不得生成结论；
- **禁止推断**：医疗效果、工程参数、量产状态、研究数据等不能从概念外推。

### Global Visual Bible

记录用途、张数、独立输出、尺寸与画幅、网格、页边距、分区、主辅风格、色值与占比、字体层级、主体形态锚点、镜头、材质、光影、图表语言、信息密度、留白和跨张连续元素。无官方尺寸时可以提出建议，但必须写明“建议规格，非赛事强制要求”。

### Board Art Direction

逐张记录评审问题、唯一主张、不重复内容、准确短文案、区域比例、阅读动线、图组数量、主体角度、局部特写、交互或结构示意、证据状态、后期排版及单张边界。区域比例合计必须为 100%。

### Constraints

分为全局禁止、项目专用禁止和赛事条件禁止。既写常见图像错误，也写当前项目最危险的误读；赛事署名、Logo、页码、模板和匿名要求只服从当届官方规则。

## 双档交付

- **完整专业版**：默认用于首次出图或交付。每张提示词展开全部执行信息，单张建议 800–1800 汉字；字数不是目标，信息闭合才是目标。
- **精简迭代版**：仅当已有一份可引用的完整专业版，且用户明确要求只调整局部时使用。必须注明继承的确认版本、保持项、修改项和禁止变化项。

快速模式只允许用显式占位符或概念假设补全底稿，不得降低最终提示词的信息密度。

## 单张自包含门槛

把任意一张复制到新的图像模型对话中，它仍须明确项目是什么、主体长什么样、输出多大、视觉如何统一、本张有哪些区域与文案、各区域占比多少、哪些信息不可生成。不得写“同上”“延续上一张”或用 `[统一基底参数]` 代替实际参数。

默认交付遵循 SKILL.md 的“综合主展板与完整带字效果稿”：先交可独立提交的综合主展板，再用分展板展开；写明总数量和实际入画文案。只有明确的素材请求或确认后的后期制作才使用无字版。
